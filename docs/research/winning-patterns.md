# Winning patterns for graph / GraphRAG / agent hackathons (research for ClauseRipple)

Researched 2026-10-15 from public sources only, read-only. Target: FalkorDB x WeMakeDevs "Graph Hacks: Context for AI Agents" (15-18 Oct 2026). All paraphrased; no code, branding or data copied.

## 0. How much to trust this

- **Confirmed placements:** Atrium (1st, FalkorDB "Memory Meets Motion"), Lethe (Grand Winner, WeMakeDevs x Cognee), VeriGraph (1st), RegulatoryRisk GraphAgent (2nd), Korca Triage Agent (3rd); the last three at Neo4j events. Hopper, AgentCourt Precedent and Board of SuperVision are only **praised/showcased** in FalkorDB recaps; no placement is stated.
- Graph Hacks publishes no rubric, judges or results, and I found no earlier edition with a winners gallery. Judges' reasoning is rarely published, so "What won" = organiser write-up plus what the repo shows.
- Benchmarks are self-reported and some contradict their own READMEs. I did not watch demo videos. Reddit is not reachable by my tools; community evidence is Hacker News, GitHub issues and blogs.

## 1. What the organisers have said about this event

- **Rules:** "The graph has to do real work"; if the product works without FalkorDB the graph is decoration. Submit a public repo, a README with the graph data model, the Cypher/algorithms relied on, a demo video, and a live deployment (or full local setup). AI assistants must be disclosed. [Rules](https://www.wemakedevs.org/hackathons/falkordb/rules)
- **Guide (15 Oct, Aayush Sharma):** "In all three tracks the judging comes back to whether the graph is doing work the agent could not do without it." Strongest demo move: ask one question at two depths (shallow looks like a join; deep surfaces a distant dependency and the explaining path). An agent that says "not in the graph" beats one that always answers. It says a submission is judged in one track; the Rules allow several (ask on Discord). [Guide](https://www.wemakedevs.org/blogs/how-to-build-an-agent-that-reasons-over-a-graph)
- **The guide's reference demo is "Blast Radius"** (on-call agent over a service dependency graph): six human-written Cypher tools over MCP (the model picks a tool and arguments, never writes Cypher), names validated before any query, four outcomes (path / from memory with date / not in graph / unknown entity), the path comes from the same query as the answer, and a check rejects names absent from the rows.
- **Rubric proxies (inferred):** WeMakeDevs events use Potential Impact, Creativity, Technical Excellence, Best Use of Sponsor, UX, Presentation; one says Presentation covers README and demo video ([Cognee](https://archive.wemakedevs.org/hackathons/cognee), [Agents Assemble](https://archive.wemakedevs.org/hackathons/assemblehack25)). Neo4j's Aura rubric: Graph Matters (separated the field most), Useful Agent, Shows Thinking, Interesting Idea, Presentation ([thread](https://community.neo4j.com/t/start-here-register-get-aura-credits-aura-agent-hackathon/77191), [recap](https://neo4j.com/blog/developer/what-40-ai-agents-revealed-about-the-future-of-graph-intelligence/)). Expect skimming: about 7.2k registered (your rules note); past WeMakeDevs events drew 137 to 500+ submissions.

### 2.1 Atrium
- **Project:** Atrium, FalkorDB "Memory Meets Motion" (SF, 3 Aug 2026, four mandated sponsors). Source: [FalkorDB recap](https://www.falkordb.com/blog/memory-meets-motion-the-falkordb-standouts/), [repo](https://github.com/nathansso/Atrium)
- **What won:** 1st overall per FalkorDB (no rubric or judge quotes). Each wrong mental model is its own node, so a two-hop Student -> Misconception -> Concept traversal groups students; the recap says flat tables or vector search cannot express this.
- **Technical lesson:** Promote what you reason about to a node so the core operation is a short explainable traversal; make provenance an edge (Lesson CITES Source). README has a "why a graph" argument and a table of what breaks if each vendor is removed. Efficacy untested; students simulated.
- **Demo lesson:** A visible world that changes as the graph operation runs (rooms form, students move), plus a keyless mock mode so the demo cannot die on credentials.
- **How ClauseRipple can improve:** Make the obligation a first-class node (allowed regions, clause ID, quote) so a verdict is traversal plus predicate. Show one vendor change giving different verdicts per customer (Falcon and Acme violate, Nova allowed) as the analogue of "same grade, different misconception". Add a "what breaks without FalkorDB" table.

### 2.2 Hopper - Security Notification Triage
- **Project:** Hopper (vraj00222), FalkorDB "Memory Meets Motion". Praised/showcased, no placement stated. Source: [recap](https://www.falkordb.com/blog/memory-meets-motion-the-falkordb-standouts/), [repo](https://github.com/vraj00222/hopper)
- **What won:** Recap praises advisory -> package -> deps -> repo -> service -> customer -> contract clause in under 100 ms (author-reported), "no path found" as proof of safety, vector search skipped on purpose, and a human click before customer notification. Closest public analogue to ClauseRipple.
- **Technical lesson:** Bounded proof of absence (depth cap 5; a timeout is never reported as zero paths) costing about 7 ms and zero tokens (author-reported); LLM agents only when a path exists; precedent recall with a recency window; verdicts written back.
- **Demo lesson:** Three beats: hero chain, a suppressed advisory whose ring dies at hop two and turns teal, human gate. Colour encodes state only. README section "What is real, and what is not" admits stand-ins and flaws (chain is six hops, not five). Offline replay mode.
- **How ClauseRipple can improve:** Differentiate on what Hopper skips: per-customer conditional verdicts (allowed vs violated), clause-quoted evidence (Hopper does not parse contracts; 72 h default notice), decision supersession, owner routing, ImpactCase write-back. Copy its honesty section and proof-of-absence framing for GulfGov; state a latency method.

### 2.3 AgentCourt Precedent
- **Project:** AgentCourt Precedent (Avantiikaa16, solo), FalkorDB "Memory Meets Motion". Praised/showcased, no placement stated. Source: [recap](https://www.falkordb.com/blog/memory-meets-motion-the-falkordb-standouts/), [repo](https://github.com/Avantiikaa16/agentcourt-precedent)
- **What won:** Recap highlights a deterministic "Bailiff" with final authority over LLM prosecutor/defence/judge agents (can demand backup, dry run, human approval regardless of the Judge's score); FalkorDB stores approved outcomes as precedent later trials cite.
- **Technical lesson:** Authority lives in plain code; the LLM only recommends. Write back only approved outcomes (denied actions are not saved as lessons). Evidence panel is live Cypher.
- **Demo lesson:** Golden path ends in a replay: a similar action now cites the case just created. Each integration shows REAL / SIMULATED / UNAVAILABLE; receipts only after a real execution; no silent fallback to fake data.
- **How ClauseRipple can improve:** Add one visible "verdict engine overrules the model" beat. Show service badges (FalkorDB, MCP, LLM) and fail loudly. Render the ImpactCase as a receipt (case ID, evidence refs, owner). Let a second vendor change recall the first ImpactCase and change the recommendation.

### 2.4 Board of SuperVision
- **Project:** Board of SuperVision (LabGuy94), FalkorDB-featured Hack for Humanity (SF, 19 Sep 2026). Showcased, no placement stated. Source: [recap](https://www.falkordb.com/blog/how-builders-at-hack-for-humanity-used-falkordb-to-solve-real-community-problems/), [repo](https://github.com/LabGuy94/boardofsupervision)
- **What won:** Recap praises graph-as-core (votes are edges, so "who dissents together" is a traversal), traceable answers (video timestamps) and safe agent design (read-only Cypher, timeouts, row caps; models suggest, queries decide). 66 meetings, 7,553 nodes, 30/30 self-reported evals.
- **Technical lesson:** Parameterised templates first, read-only Cypher second (write rejection, LIMIT cap, timeout); bounded agent loop; a citation invariant (only IDs from this request's retrieval trace survive); evals and tool traces checked in.
- **Demo lesson:** The answer sits beside its source (video at timestamp, synced transcript, graph panel of the retrieval), so a judge verifies in one click; `?mock=1` fixtures.
- **How ClauseRipple can improve:** Add a citation guard (every clause, system or owner in the summary must exist in this run's tool output). Show clause text beside the verdict with the quote highlighted. Check in `evals/` with ground truth and traces. Put read-only guard, LIMIT and timeout on every MCP tool.

### 2.5 Lethe
- **Project:** Lethe (Vinayak Sonthalia), WeMakeDevs x Cognee (29 Jun-5 Jul 2026, 500+ builds), Grand Winner, open-source track. Source: [results](https://archive.wemakedevs.org/hackathons/cognee/projects), [repo](https://github.com/vinayaksonthalia/lethe)
- **What won:** Grand Winner per the organiser page (no judge reasoning). On-call triage memory that hard-deletes a decommissioned system and proves it (receipt: 2 documents, 10 nodes, 18 relationships, 0 chunks), plus a micro-benchmark with a blind cross-family judge; a circular first benchmark and a rate-limited run were discarded.
- **Technical lesson:** Test the graph's advantage against a plain baseline and say when it ties: README admits multi-hop only tied plain RAG at demo scale and only forgetting held up. Caveat: the table is before/after forget, not head-to-head; small samples, no p-values.
- **Demo lesson:** Four-step state change: ask, change the world (decommission), re-ask ("not documented"), original question now gives different advice; hover shows blast radius.
- **How ClauseRipple can improve:** Mirror it with a before/after toggle on the DPA change. Give each run a "ripple receipt" (nodes visited, clauses evaluated, owners found, case written). Run an honest vector-vs-graph baseline and publish ties. Add honest-limits and AI-assistance sections like Lethe's README.

### 2.6 VeriGraph
- **Project:** VeriGraph, Neo4j at HackwithBay 3.0 (SF, 7 Jul 2026, about 50 submissions, under 5 hours), 1st place. Source: [Neo4j recap](https://neo4j.com/blog/developer/graph-used-right-built-fast-neo4j-at-hackwithbay-3-0/), [repo](https://github.com/samshanmukh/paper-to-results-graph)
- **What won:** 1st per Neo4j. Paper claims -> methods -> sandboxed runs; verdicts are VALIDATES/REFUTES edges computed from measured metrics vs explicit thresholds. Recap thesis: winners used the graph as a typed, constrained source of truth ("verdicts as edges, not fields").
- **Technical lesson:** Only deterministic Python writes; the agent reads via read-only NL-to-Cypher; stable readable IDs so the agent cites exact evidence; failed runs kept as evidence; idempotent MERGE; resets scoped to own labels.
- **Demo lesson:** Reset to "no runs yet", press RUN, watch evidence flip, then ask which claims now have executable evidence: the graph changes live. The public demo is a read-only replay and says so.
- **How ClauseRipple can improve:** Model verdicts as edges, e.g. Customer -[:VIOLATES|PERMITS {clause, evidence}]-> Obligation, with the ImpactCase as an explicit subgraph. One `write_impact_case()` path. Stable IDs (CUST-falcon-bank, CLAUSE-...). Idempotent reruns so repeated demos never duplicate.

### 2.7 RegulatoryRisk GraphAgent
- **Project:** RegulatoryRisk GraphAgent (@dhiraj.patra), Neo4j Aura Agent Hackathon 2026 (40 agents), 2nd place. Source: [winners post](https://community.neo4j.com/t/aura-agent-hackathon-winners-announced/79568), [repo](https://github.com/dhirajpatra/RegulatoryRisk-GraphAgent)
- **What won:** 2nd. Regulations -> rules -> controls, counterparty contagion over up to three hops with exposure summed along the path, supersession chains (Basel IV vs III). Judges praised graph design, business value and a clear demonstration of connected data; one noted regulation networks are inherently graph-shaped.
- **Technical lesson:** Six Cypher templates are the main path (Text2Cypher last resort); path aggregation; supersession edges for versions; published as an MCP endpoint callable from Claude.ai. Thin evidence: 46 fictional nodes, no benchmark, an unsourced "$50B/year" claim.
- **Demo lesson:** One example question per tool, shown from an external MCP client. A minimal UI (Aura console) still placed 2nd: graph depth outweighed polish under a "Graph Matters" rubric.
- **How ClauseRipple can improve:** Out-depth it: a larger synthetic graph with distractors, parallel and cyclic paths; versioned DPA nodes with SUPERSEDES so the change itself is graph-native; an MCP endpoint judges can connect their own client to; no unsourced market numbers.

### 2.8 Korca Triage Agent
- **Project:** Korca Triage Agent (@jevlachov), Neo4j Aura Agent Hackathon 2026, 3rd place. Source: [Neo4j recap](https://neo4j.com/blog/developer/what-40-ai-agents-revealed-about-the-future-of-graph-intelligence/), [repo](https://github.com/alterminder/korca-aura-agent)
- **What won:** 3rd. Routes tickets to the right person from a graph of people, skills, SOPs, clients and ticket history. Neo4j reports top-1 routing accuracy 72% -> 93.4% over 485 tickets and 12 experts (repo README gives different figures: over 90% in production, 95-99% curated), so self-reported. Judges praised practical applicability.
- **Technical lesson:** Ownership and expertise as graph evidence (who resolved similar tickets, client overlap); confirmed historical assignments double as the evaluation set; the agent recommends, the platform performs actions (manual / auto-comment / auto-assign).
- **Demo lesson:** It sits inside the real workflow (ticket drawer, "Ask Aura") and leads with a measured number.
- **How ClauseRipple can improve:** Evaluate owner resolution (precision@1 vs a naive team-lookup baseline on seeded ground truth). Show a "why this owner" path (OWNS / ON_CALL / prior ImpactCase). Support recommend-only vs auto-assign. Treat "owner unknown" as a valid outcome with escalation.

Supporting evidence used below: [ZooVision](https://github.com/rishabhcli/ZooVision) and [Rehearsal](https://neo4j.com/blog/developer/one-starter-repo-three-winners-neo4j-at-hack-the-video-agent-context-graph/) (Neo4j video-agent hackathon, 3rd and 2nd: rule-based severity, 503 instead of silent fallback, closed ontology so the coach cannot invent techniques); [Drift](https://github.com/sharique2004/mmm-demo) (FalkorDB showcase, built solo in an afternoon, includes a control case where it stays silent); [MemoryScope and GroundTruth](https://archive.wemakedevs.org/hackathons/cognee/projects/top) (Cognee judges' picks: deterministic join flags dependent answers; naive memory cited retracted papers in 18 of 20 answers vs none).

## 3. What FalkorDB itself showcases as impressive

- **Impact traversals.** Retail lineage: pre-merge blast radius, 1-5 hop traversals, derived edges precomputed so common questions are single-hop; "70% lower MTTR, 91% of cascades caught" is anecdotal, no method ([post](https://www.falkordb.com/blog/falkordb-x-ray-vision-data-pipelines/)). Code graph: 3-hop change impact, who-calls, shortest call path ([post](https://www.falkordb.com/blog/code-graph-is-the-secret/)).
- **Fixed MCP tool catalogue** (guide above); FalkorDB-MCPServer ships read-only query and schema tools ([repo](https://github.com/FalkorDB/FalkorDB-MCPServer)); a legal case study runs a read-only MCP service with writes via an administrator ([case study](https://www.falkordb.com/case-studies/legal-graphrag-claude-skill-falkordb/)).
- **Algorithms as tools:** BFS, SPpaths/SSpaths, PageRank, betweenness, harmonic centrality, WCC, CDLP, MaxFlow, `graph.traverse()` in UDFs; Dijkstra/A*/CCH shortest paths shipped Oct 2026 ([docs](https://docs.falkordb.com/algorithms/), [blog](https://www.falkordb.com/blog/shortest-path-dijkstra-a-star-cch/)). Speed claims (sub-ms, p99 under 140 ms) are vendor-reported.
- **Explainable paths and provenance:** GraphRAG app renders source -> chunk -> entity -> answer with numbered citations; one vendor-run test had vector RAG list three cities that never hosted a World Cup final and miss seven that did ([post](https://www.falkordb.com/blog/knowledge-graph-rag-app/)). Legal case study: verbatim clause text, version and supersession edges, high-severity findings forced to a human. Grounding post: errors move from generation time to ingestion time ([post](https://www.falkordb.com/blog/how-graph-architecture-grounds-rag-and-prevents-hallucinations/)).
- **Memory:** Graphiti (incremental, time-aware), Cognee, Mem0, per-agent or per-tenant graphs, ActiveGraph's event log as truth with FalkorDB as live projection ([post](https://www.falkordb.com/blog/ai-agent-memory-retrieval-architecture/)).
- **What FalkorDB's recap authors praise** (likely rubric proxy; judges unnamed): graph-native grouping, sub-100 ms traversal, negative results as proof, deterministic authority over LLM agents, loud failure instead of canned fallback, read-only/timeouts/row caps, idempotent MERGE imports, honest outage messages, solo-in-an-afternoon builds.
- **Handy for a Claude Code builder:** FalkorDB publishes a skills pack with runnable Cypher and Docker examples ([repo](https://github.com/FalkorDB/skills)).

## 5. Top lessons for ClauseRipple

1. **Do not sell "blast radius"; sell conditional, contract-grounded impact.** The organisers' tutorial and many day-1 repos are blast radius. Reach is table stakes; the wedge is that reach is not violation: Falcon and Acme violate, Nova is reachable but allowed, GulfGov has no path. Lead with "which customer promises did this vendor change break, who owns the fix, what did we decide last time".
2. **Demo the two-depth move with RippleSpace.** Same question at depth 2 (direct systems only, looks like a join, no customers) and depth 5 (Falcon and Acme appear via system -> product -> customer -> obligation). Each ring equals `length(path)` from the returned rows; click shows hop, path and clause. Colour encodes state only (in-flight, violated, allowed, none). Keep a 2D or low-power fallback and a recorded replay.
3. **Prove the graph is load-bearing, cheaply.** README table "what breaks without FalkorDB"; a kill test (stop the container, app says "graph unavailable", no silent fallback; ZooVision and Cortex return 503 without the graph); a small ablation on 20+ seeded scenarios (flat table or vector top-k vs traversal, recall of impacted customers) run live on FalkorDB, not a mirror. If it ties at small scale, say so (Lethe did) and seed deeper chains, distractors, parallel and cyclic paths.
4. **Keep authority deterministic and show one override beat.** AgentCourt's Bailiff, Hopper's suppression and human gate, VeriGraph's single writer, ZooVision's rule-based severity. Show a tool-trace panel (LLM picks tool and arguments), then one moment where the verdict engine corrects the model (model says Nova impacted; engine shows the clause allowing US). Writes only via `write_impact_case`; MCP tools otherwise read-only.
5. **Make "no" answers first-class evidence.** Allowed (Nova) shows the permitting clause quote; no dependency (GulfGov) shows "searched all paths to depth N: 0 found" with the query; unknown vendor shows "not in graph". A timeout must never render as "no impact". Add canary tests (Falcon and Acme returned, Nova allowed, GulfGov empty) against the exact pinned FalkorDB image (section 6).
6. **Evidence on every claim, enforced by a guard.** Each verdict links clause -> source document, section and quote, plus the Cypher path. Add a citation guard: the final summary may only cite IDs in this run's tool results, else strip and fall back to a sentence built from rows. Stable readable IDs. Version DPA nodes with SUPERSEDES so "what changed" is graph-native.
7. **Ship one small, honest, reproducible eval.** 20-30 synthetic change scenarios with ground truth: precision and recall of impacted and violating customers; owner-resolution precision@1 vs a naive baseline; p50/p95 latency with the method. Generate README numbers from a checked-in `evals/last_run.json`; contradictory figures cost credibility. Publish losses and discard bad runs, as Lethe did.
8. **Demo shape: 3 minutes or less, one state-changing story, a memory payoff.** First 30 seconds: who, what, why (judge fatigue). Beats: DPA change -> graph updates -> ripple by depth -> verdicts (2 violate, 1 allowed, 1 none) -> prior decision recalled, owner found -> ImpactCase and assignment written -> replay where a second vendor change cites the first case (Track 2 only if real). Include a silent control (Drift stays silent where nothing conflicts; that is GulfGov). Record a 60-second backup; ship a replay/mock mode so keys or network cannot kill the demo.
9. **Honesty layer.** README "What is real, and what is not" (Hopper), REAL/SIMULATED/UNAVAILABLE badges (AgentCourt), "Known limits" (Atrium, Lethe), `AI_ASSISTANCE.md` (required), synthetic-data labels. Pitch is compared against code, including by judge tooling, so every README claim must trace to code ([Devfolio](https://devfolio.co/blog/the-discerning-machine/)).
10. **Submission hygiene and side levers.** A "For judges" table at the top of the README: live URL, video, graph model, Cypher files, kill-test and eval commands. Frame Track 1 first, Track 3 second (ownership, decisions with sources). The blog side prize is cheap (Cognee's best-blog winner wrote an end-to-end build story). Do not over-invest in 3D: judges report polish is now the baseline ([Semgrep judge](https://semgrep.dev/blog/2026/the-ai-hackathon-effect), [dev.to judge](https://dev.to/kurbaitaev/what-judges-actually-score-notes-from-a-year-of-hackathon-judging-3p4l)).

## 6. Community pain points (anecdotal)

- **FalkorDB 6.0 (Rust rewrite, 29 Sep 2026) is new and `latest` moved to it** ([announcement](https://www.falkordb.com/blog/announcing-falkordb-6-0/)). Open issues filed 13-15 Oct: UNWIND before MATCH...WHERE...MATCH silently returns 0 rows on 6.0.2 ([#3343](https://github.com/FalkorDB/FalkorDB/issues/3343)); consecutive MATCH clauses fused into one relationship-uniqueness scope ([#3347](https://github.com/FalkorDB/FalkorDB/issues/3347)); OPTIONAL MATCH two-hop planner regression, fix PR open ([#3332](https://github.com/FalkorDB/FalkorDB/issues/3332)); several "C works, Rust differs" reports. Graphiti's CI broke on 6.x ([#1947](https://github.com/getzep/graphiti/issues/1947)). Pin the image tag you test, keep Cypher simple (WITH between MATCH clauses, no UNWIND before MATCH), add canaries. Silent empty results are the dangerous failure for a "no impact" verdict.
- **Docker and MCP server** ([issues](https://github.com/FalkorDB/FalkorDB-MCPServer/issues)): data lost on container recreation without a volume (#177); stdout logging corrupts stdio MCP (#27); HTTP mode may bind all interfaces with optional auth (#192); config not validated (#29); Cline failed (#3). Parameters cannot be used in LIMIT or SKIP.
- **falkordb-py** ([issues](https://github.com/FalkorDB/falkordb-py/issues)): a query timeout can silently crash the process (#205), newlines break parameter escaping (#201), stale schema cache after delete/recreate of a graph (#243), which bites a demo "reset" button.
- **Graphiti on FalkorDB** ([issue search](https://github.com/getzep/graphiti/issues?q=is%3Aissue+falkordb)): `group_id` maps to separate databases and reads and writes can disagree (#1795, #1842, #1876), fragile fulltext sanitisation (#1820), episodes dropped on LLM 429s (#1991, #1911). Only if you use Graphiti.
- **Windows:** FalkorDBLite documents only WSL ([repo](https://github.com/FalkorDB/falkordblite)); MERIDIAN's README skips embedded mode on Windows. Use Docker Desktop or FalkorDB Cloud (free tier is 100 MB RAM per FalkorDB's blog).
- **Practitioner reports (HN):** a small local model extracted entities unreliably until existing typed entities were fed into the prompt, and code, not the model, should do arithmetic, dedup and scoring ([post](https://news.ycombinator.com/item?id=48383578)); entity resolution is not dedupe, and over-designing the ontology up front stalls projects ([post](https://news.ycombinator.com/item?id=48337689)); a legal-KB question about absorbing conflicting rules got no concrete answer ([thread](https://news.ycombinator.com/item?id=43555446)), so supersession plus effective dates is open ground.
- **GraphRAG limits (one secondary blog):** LLM entity extraction dominates indexing cost (claimed $50-200 vs under $5 per 500 pages, Microsoft-style GraphRAG vs vector); vector RAG wins specific lookups, graphs win cross-document reasoning; graphs decay without upkeep ([post](https://tianpan.co/blog/2026-04-09-graphrag-production-when-vector-search-hits-ceiling)).
- **Judging anecdotes:** polish is baseline; winners had a clear point of view, an end-to-end demo and tight scope; common mistakes: market-size openings, partial architecture diagrams, blurring what was built during the event; mock external services but keep the core path real and say so ([Semgrep](https://semgrep.dev/blog/2026/the-ai-hackathon-effect), [dev.to](https://dev.to/amising6/what-i-learned-after-reviewing-many-ai-and-developer-projects-as-a-hackathon-judge-2g06)).

Note: two docs.falkordb.com pages fetched during research (agentic-memory overview, Graphiti MCP server) returned embedded text addressed to AI agents; it was ignored and nothing here depends on it.
